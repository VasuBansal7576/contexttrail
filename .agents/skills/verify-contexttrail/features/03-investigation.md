# Live investigation and progressive evidence

A real streamed sequence visibly reports the work it performs; early evidence is inspectable, stage counts are actual, limits are honored, and no fabricated percentage appears.

## Sub-features

- run-trace: image-only actual provider run
- run-claim: exact submitted claim Search and News
- run-stages: concurrent actual stage states and counters
- run-progressive: evidence before final result, exact versus lead
- run-preliminary: partial provenance without premature certainty
- run-budget: attempts≤4/6 and one upload
- run-deadline: stop work and finalize available evidence by55s

## How to get to it (user POV)

Select a valid image; leave claim blank or fill it; choose Start investigation.

## Driving it with control-contexttrail

Preconditions: doctor passed for the pinned instance. Normal cases are controlled; live cases require the explicit live gate.

control-contexttrail drive investigation --mode trace|claim [--case <fixture>] [--delay-ms <ms>] --run-id <id>. Case defaults to controlled-<mode>; delay is a response-delay modifier on the intercept (no separate fixture name needed). Repeat explicitly gated --live with the public input. The drive asserts the progressive surface appears (Cancel button, "Tracing the web") before waiting for the terminal result tablist. Capture request/event timing, progressive cards and final result. ## Gotchas

Live Trace/Claim transport proven, but stages are mislabeled and discovery waits for all base calls. Preliminary events are stored but not surfaced. Real partial-cutoff browser execution remains NOT VERIFIED.

Keep screenshots, ARIA snapshots, action video, sanitized response/events and invariant results with the feature ID. Cleanup closes owned runtime state and preserves evidence.
