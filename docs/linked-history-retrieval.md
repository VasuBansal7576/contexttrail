# Inspected historical source links

Deep reading retains up to 12 safe HTTP(S) source references. Anchors and iframes keep their original document index and complete paragraph, blockquote or figure support (at most 1200 characters). Explicit article/main containers remain supported. For articles rendered with other wrappers, both the same URL and complete supporting container must survive together in the article chosen by Readability. Navigation, hidden content, fragment-only references, credentials, sensitive URL parameters, nonpublic literal addresses, invalid URLs and oversized supporting containers are omitted. The fetched URL resolves relative references; an untrusted HTML base tag cannot rewrite the source. DNS safety is checked again by the normal pinned page fetcher.

Structured media references can also be read from a recognized `cards` / `story-elements` schema in nonexecuted `application/json` state. The owning story must explicitly identify the fetched resource; a contradictory canonical URL rejects it. Each card needs an unambiguous original DOM ID. Only an explicit safe media `url` or `embed-url` is retained, with its script index and JSON pointer. The immediately preceding text item supplies its closest complete paragraph. That paragraph must occur uniquely in the original card and survive verbatim in the chosen readable article; missing, oversized, repeated or intervening support cannot make an earlier historical paragraph attach to another media item. No URLs are derived from video IDs, titles, dates or plain mentions.

State parsing admits at most eight JSON scripts, 512 KiB per script, 512 visited objects/arrays, depth eight, sixteen cards and sixty-four items per card. Oversized card/item collections fail closed; unrecognized shapes, ambiguous owners and unsupported layouts remain unresolved. The twelve-reference cap is shared with DOM links. Structured references follow DOM references in the unchanged selection order, so an earlier admissible DOM historical reference can consume the fifth read before a structured reference.

A reference containing media/post language and an explicit year or earlier/original temporal language is a historical **lead**. That rule selects work; it proves neither a historical date nor media identity. The 12-reference retention prefers historical leads over unrelated references, preserving document order within each class. A later historical reference to the same URL replaces an earlier unrelated supporting span. No names, dates or titles generate URLs or search queries.

## Selection and bounds

All frozen deep-read priorities stay in place: the core anchor, qualifying conflict, strong support, fact-check and current-reporting winner, followed by undated core recovery when no dated core exists. Only after those priorities, when there is no dated core, one already-retained historical media lead may use an otherwise unclaimed filler slot. It requires a model judgment with relevance at least 0.70, a safe retained HTTP(S) source URL, and the same generic media/temporal cue as inspected links in its combined title/snippet (at most 1200 characters). Relevance, provider rank and evidence ID retain the existing stable tie-break order. If a qualifying historical lead already won an earlier priority, no additional cue slot is reserved. Ordinary filler completes the plan. This improves the opportunity to inspect a historical article during the initial reads without inventing a source or increasing retrieval capacity.

After the first four selected reads finish, one inspected historical link may use the fifth page slot. If no link is admissible, the planned fifth candidate is read. Parent model relevance, parent canonical URL and reference document order determine a stable order, independently of network response timing or publisher reputation. Already-read links are skipped. A new linked candidate is admitted only when there is space in the existing five contextual search retention slots and the 24 distinct-candidate classification allowance; at most one source-link candidate is retained. A retained candidate reached again by its inspected link keeps its independently acquired identity.

There is one hop, at most five page attempts, no extra search or upload, and the existing shared deadline/signal. The existing 24 distinct-candidate classification allowance and live worst-case request reservation remain unchanged. A page slot can classify a newly acquired linked resource instead of refining the ordinary fifth candidate. No additional semantic work is dispatched after the deadline. This does not guarantee reaching every older source: references outside the first four selected pages, the 12-link retention or free contextual capacity can remain unresolved.

The page-read audit records selected, already-read, retention-limited, classification-limited, page-limited, deadline-limited and unrelated references. A selected reference points to a separate candidate/page-read audit, whose fetch/extraction/binding failure remains visible. References found on the final page are retained but never recursively followed.

## Dates and identity

An article publication date belongs to its fetched resource. A year/event date reported in its text remains supporting text; it is never copied to a linked post. A linked post receives only its own bound JSON-LD/meta publication date or explicitly publication-marked time element outside quoted/embedded content whose owning microdata scope identifies the fetched resource. Rejected time-owner bindings stay inspectable. Entity binding preserves post-ID query parameters and case-sensitive paths. JSON-LD dateCreated, generic date metadata and generic time elements cannot stand in for publication, so creation/filming and reported event times remain distinct and unresolved unless separately evidenced.

A newly followed source is contextual (`source_link`) and has no media identity. A fact-check title, old year, embedded reference or hash resemblance cannot promote it. Independently retrieved Lens exact identity may still qualify on the *same* linked resource. The spatial verifier remains disabled pending its measured acceptance; this work does not claim to verify a newly linked video. Source-link dates alone do not enter the core media chronology. Shared text/attribution continues through the existing origin grouping and cannot create independent corroboration merely from another domain.

## Verification and outstanding #10 acceptance

Offline tests exercise a retained historical article reaching an inspected original-source link within five attempts; unchanged frozen and undated-core priorities; stable cue ties; low-relevance, unclassified, unsafe, oversized and nonhistorical controls; a separately dated contextual post; a linked occurrence independently reported by Lens exact collection; failed/empty/rejected reads; retention, one-hop/page/deadline limits; event/publication separation and shared-origin counterexamples. They inject finite search/classification/page responses and make no provider calls. The historical cue and a successfully acquired article date still leave unverified media outside the core chronology.

The structured-reference fixture is a reduced October 3 inspection of [the retained Quint article](https://www.thequint.com/news/webqoof/old-video-of-mcd-demolition-in-jasola-falsely-shared-as-one-of-satya-niketan-building-collapse-fact-check), with a companion provenance record. This later HTTP 200 inspection produced 1,671 readable characters; the previously captured investigation retained 1,665 and no original HTML. These are distinct observations. The inspected HTML has no article/main root, a visible YouTube anchor in its readable paragraph, and another explicit YouTube URL in bound JSON media data. The closest paragraph for that structured media item has no temporal cue, so the URL remains inspectable but is not assigned historical priority. No case-specific priority, historical date or media identity is inferred. Generic injected controls prove fifth-read selection and live/saved raw-report roundtrip without claiming the real original clip was recovered.

The actual historical-reuse workflow has **not** been demonstrated by these fixtures. Issue #10 stays open. Bounded inspection and acquisition improve an opportunity, while a separately authorized trial must still establish a source-backed original URL and measured media relation, retain requested/final URL binding and dates, and report the actual search/retention limits. A new spatial verifier must be evaluated before enabling identity promotion. The historical trial is not hardcoded and provider requests are not part of issue triage.
